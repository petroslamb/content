# Phase 2.5 — Local Cockpit

## Goal

Add a thin local browser surface over package state, pending gates, recent runs, and validation health.

The cockpit is a reader and approver over filesystem-backed truth. It is not a second system of record and should not lead the design of runtime artifacts.

## Primary Plan

[`dashboard-v0.md`](dashboard-v0.md) is the detailed cockpit v0 scope.

This file exists to keep the numbered Phase 2 sequence complete and to define the dependency boundary between 2.4 and 2.5.

## Dependency Rule

Do not build the cockpit until 2.4 has stable file-backed runtime behavior for:

- `content-agent status`
- `content-agent next`
- `content-agent review list`
- `content-agent review inspect`
- gate approval, rejection, and deferral
- recent run-record reading

The cockpit should call or mirror those runtime readers rather than reimplementing authority rules independently.

## Required Views

Cockpit v0 should expose:

- package lifecycle state
- selected route or next action
- pending and recently resolved review gates
- recent run records
- validation health
- preview and evidence artifact links

Data sources:

- package `status.yaml`
- workflow `workflow.yaml`
- root policy/profile/gate YAMLs
- `reviewable-runs/resolved-runs/`
- `reviewable-runs/logs/`
- `reviewable-runs/gates/`
- `content-agent` JSON output

## Slice 1 Read-Only Surface

The first implementation slice is intentionally narrow:

- `./content-cockpit` starts a localhost browser surface.
- `npm run cockpit` is the package-script entrypoint.
- `scripts/content_cockpit.py` imports the existing `content-agent` readers instead of parsing authority files independently.
- the browser view shows status data, review gate lists, recent run records, validation health, and artifact links.
- safe validation reruns call `content-agent validate`.
- gate decisions call `content-agent review approve`, `content-agent review reject`, or `content-agent review defer` with a required decision reason.

This slice has no arbitrary job runner and no package lifecycle mutation path beyond existing `content-agent review` semantics.

## Minimum Actions

The cockpit may support:

- open package
- open preview artifact
- open evidence artifact
- inspect gate
- approve gate
- reject gate
- defer gate
- rerun safe validation

Gate mutation actions must go through the same decision semantics as `content-agent review`.

## Constraints

- local-first
- no cloud dependency
- no hidden second record
- no analytics-first dashboard
- no general arbitrary job launcher
- no content editor in v0

Indexes and caches are allowed only when rebuildable from file-backed truth.

## Acceptance Read

2.5 is done when:

1. pending gates are visible without reading terminal logs
2. recent runs are inspectable from one local view
3. gate decisions can be made against exact gate artifacts
4. validation health is visible without changing package state
5. the cockpit can be rebuilt or refreshed from files
6. filesystem YAML and package files remain the authority surface

## Non-Goals

- no user accounts
- no workspace sharing
- no cloud orchestration
- no autonomous execution
- no full article editing UI
- no replacement for `content-agent`
