# Phase 2.3 — Trace And Provenance Minimums

## Goal

Add the minimum trace structure needed for semantic debugging without pretending that the repo already has full provenance graphs.

Traces remain derivative debugging records. They do not become the source of truth.

## Deliverables

- run records that include context paths and hashes
- workflow version or hash in run records
- parent artifact ids where a step consumes prior outputs
- validation results recorded in the trace
- gate ids recorded in the trace when a review stop is reached
- a stable small vocabulary for promoted-output state:
  - `authority_order`
  - `claim_state`
  - `contradiction_state`
  - `validation_state`
  - `trace_state`

## Trace Minimum

Every platform-path run should be able to record:

- which context files were loaded
- which contract version governed execution
- what artifacts were consumed
- what validators ran
- what gate stopped the run, if any

That is the minimum useful source-linked debugging surface.

## Provenance Minimum

Phase 2 should start with a small promoted-output state model, not full graphs.

This state model should be usable for:

- promoted claims
- publish approvals
- major draft promotions
- any other output that crosses an irreversible or trust-sensitive boundary

The storage surface is still open, but the vocabulary should be fixed here.

## Acceptance Read

2.3 is done when:

1. run records consistently include the trace minimum fields
2. gate-linked runs preserve the gate id in the trace
3. the promoted-output state vocabulary is stable and documented
4. traces can support source-linked debugging without being misdescribed as source

## Non-Goals

- no full semantic provenance graphs
- no automatic contradiction resolution
- no claim that logs are the authority surface
- no analytics product layer
