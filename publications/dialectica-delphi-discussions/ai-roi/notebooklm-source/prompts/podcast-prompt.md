# NotebookLM Podcast Prompt

Create a short deep-dive audio overview for Pere Molisn Ayuso and Michael Petychakis at Dialectica.

Use only the uploaded AI ROI Delphi prototype sources. Do not bring in external AI ROI frameworks, generic vendor language, or broad AI strategy commentary.

The goal is to help Pere and Michael understand the worked example without reading the full markdown packet. The audio should feel like a practical briefing, not a public podcast episode and not a showcase of Petros's work.

## Length And Shape

Target 6-8 minutes.

Use a calm two-person deep-dive format if NotebookLM requires hosts. Keep the hosts direct and non-theatrical.

Do not mention raw participant names, private company details, raw quotes, pricing, title negotiation, compensation, or private career material.

Do not frame the artifact as client-ready. This is a private operator prototype.

## Required Arc

Opening, 30-45 seconds:

Explain that Pere shared Delphi session material, and the AI ROI session was processed as one worked example of a Delphi operating loop.

Part 1, about 1 minute:

Explain the AI ROI insight. The value of the session is not a generic claim that AI makes engineering faster. The useful issue is where ROI disappears after one task gets faster: review, QA, release, security, token governance, and adoption.

Part 2, about 1.5 minutes:

Explain what one session becomes:

```text
source record -> reviewed claims -> artifact options -> give/get actions -> expert memory -> better next room
```

Make clear that this is an operating layer around expert participation, not a pre-decided software platform.

Part 3, about 1.5 minutes:

Give a few concrete artifact examples from the packet:

- a reviewed claim about AI-written code percentage being a weak proxy for productivity
- an artifact option such as an AI ROI metric map or attendee recap
- a give/get action asking participants where ROI disappears in their organization
- a data model instance tying session, claims, artifacts, and actions together

Part 4, about 1 minute:

Explain Michael's evaluation path: baseline the current workflow, find the bottleneck, keep human review and compliance in the loop, measure whether the process improves, and use evidence for build-versus-buy.

Part 5, about 1 minute:

Explain Pere's community path: give experts a useful anonymized output, ask for one narrow signal back, segment follow-up, and use the result to form better smaller rooms.

Close, 30-45 seconds:

End with the practical decision:

```text
The next question is not whether to build a full Delphi platform. The next question is whether to test one real session end to end inside Dialectica's systems for 30-45 days.
```

## Tone

Practical, sober, and helpful. No hype. No sales language. No generic AI enthusiasm.

Avoid phrases like unlock, transform, revolutionize, game-changing, seamless, cutting-edge, powerful, future-proof, or rich discussion.
