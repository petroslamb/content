# NotebookLM Explainer Video Prompt

Create a very tight private explainer video for Pere Molisn Ayuso and Michael Petychakis at Dialectica.

Use only the uploaded AI ROI Delphi prototype sources. Do not use external AI ROI frameworks, vendor claims, generic AI strategy commentary, raw participant quotes, participant names, company names from the room, pricing, compensation, title negotiation, or private career material.

The purpose is to help Pere and Michael understand the practical operating option. This is not a public video, not a client-facing AI ROI explainer, and not a portfolio showcase. Petros's work is the medium; the useful output is a decision aid for their Delphi problem.

Target length: 4-6 minutes.

Style: clean operational explainer. Use simple diagrams, process flows, and a final matrix. Avoid generic robot imagery, futuristic AI stock visuals, exaggerated music, sales language, and cinematic hype. Make it feel like a concise technical briefing.

## Core Message

Pere shared Delphi session material. The AI ROI session was processed as one worked example. The question is whether one real Delphi session can become structured memory, safe reuse, targeted follow-up, and a better next room before Dialectica discusses a larger platform.

## Required Structure

### Segment 1: Intro, 20-30 seconds

Open with the practical context:

```text
This is a worked example of how one Delphi session can become an operating loop.
The example is the AI ROI session.
The goal is to help Pere and Michael decide what to test next.
```

Make clear that Delphi here means the live session format plus a possible operating layer around it, not a finished platform.

### Segment 2: The Problem, 35-45 seconds

Explain the failure mode:

```text
High-signal sessions decay into recordings, notes, summaries, and generic follow-up unless the system preserves what was learned and what should happen next.
```

Use a simple visual:

```text
high-signal session -> raw recording / disconnected notes / generic recap / generic follow-up
```

Then name the alternative:

```text
The opportunity is to turn session material into structured expert-network memory.
```

### Segment 3: The Five-Step Operating Loop, 45-60 seconds

Show the whole loop first:

```text
source record -> claim map -> artifact map -> give/get actions -> expert memory -> better next room
```

Explain each step in one sentence before going deeper:

1. Source record: preserve the raw session and handling boundaries.
2. Claim map: turn discussion into reviewed claims with confidence, sensitivity, audience, and review status.
3. Artifact map: decide which outputs are useful and safe for each audience.
4. Give/get actions: turn insight into a participant exchange.
5. Expert memory: write the useful signal back into the network so the next room improves.

### Segment 4: Step 1 And 2, 60-75 seconds

Explain source record and claim map together.

Use the AI ROI insight:

```text
AI ROI often disappears after code generation, in review, QA, security, deployment, token governance, and adoption.
```

Make the technical point:

```text
The system should not treat every transcript line as reusable. It should preserve the source, extract claims, and review them before reuse.
```

Concrete example:

```text
Claim: AI-written code percentage is a weak proxy for business productivity.
Review state: high confidence, medium sensitivity, numeric examples need review before external use.
```

### Segment 5: Step 3 And 4, 60-75 seconds

Explain artifact map and give/get actions together.

Artifact examples:

- AI ROI metric map
- attendee recap
- token governance checklist
- internal operator note

Give/get example:

```text
Give participants an anonymized AI ROI map or short memo.
Ask one focused question back: where does AI ROI disappear in your organization?
```

Explain why this helps Pere:

```text
The answer segments follow-up and makes a smaller, more valuable room possible.
```

### Segment 6: Step 5 And Michael's Test, 60-75 seconds

Explain expert memory and the 30-45 day technical test.

Use this structure:

```text
Baseline: how does a session become useful output today?
Bottleneck: where does the workflow stall?
Prototype: keep a human operator, review, and compliance in the loop.
Measure: operator time, claim correction rate, artifact usefulness, follow-up response, and next-room quality.
Decide: what should Dialectica build, buy, or keep manual?
```

Make clear that this is a content, data-model, and operator-workflow prototype, not software pretending to be finished.

### Segment 7: Concluding Matrix, 60 seconds

End with a matrix that brings everything together. Show this as a simple table.

Table title:

```text
What One Session Proves
```

Columns:

```text
Layer | Artifact | Michael evaluates | Pere uses | 30-45 day signal
```

Rows:

```text
Source record | reviewed session object | source quality and handling boundary | session memory starts clean | source-to-output time
Claim map | reviewed claims | confidence, sensitivity, review quality | reusable insights without attribution risk | correction rate
Artifact map | memo / recap / checklist | output usefulness and reuse constraints | value returned to experts | usefulness rating
Give/get actions | bottleneck follow-up | response and workflow fit | segmentation and smaller room formation | response rate
Expert memory | session/expert/action state | build-versus-buy and data model validity | better next invitation | next-room quality
```

Close with the decision:

```text
The next question is not whether to build a full Delphi platform. The next question is whether to test one real session end to end inside Dialectica's systems for 30-45 days.
```

## Tone Rules

Use practical, sober language. No hype.

Avoid words and phrases such as unlock, transform, revolutionize, game-changing, seamless, cutting-edge, powerful, future-proof, rich discussion, and AI revolution.

Do not overpraise Delphi. Keep the argument conditional: this is worth testing if the loop improves real workflow, expert follow-up, and next-room quality.
