## Promise

The candidate will argue that a governed proof run is the reviewable source surface for autonomous content work. The point is not that an agent transcript becomes trustworthy when it is long or impressive. The point is that trust starts when the run exposes the declared workflow, admitted context, bounded tools, validation hooks, review gates, and resume evidence that let a human decide whether lifecycle movement is warranted. This frame survives pressure because it does not ask the reader to believe in autonomous publication as a finished capability. It shows a narrower object: a local governed runtime that can stop before important movement and leave inspectable evidence behind.

## Spine

1. Open on the difference between a completion transcript and a proof record.
2. Define the proof run as a source surface: workflow contract, package state, policy, gates, profile, runtime, evidence.
3. Walk through the repo's Phase 2 proof anatomy without turning the essay into internal documentation.
4. Place that anatomy in the research backdrop: specification-driven construction, context-grounded workflows, long-horizon reliability gaps, schema gates, and specification-anchored audits.
5. Explain gates as lifecycle boundaries, not process decoration.
6. Close with the bounded claim: this proves a governed local path through reviewable evidence, while publication reliability still requires later stage proof.

## Paragraph burden

The opening must make the reader feel why a raw transcript is too weak to authorize package movement. The architecture section must name each source surface in plain language without flattening them into one manifest. The local proof section must show what the Phase 2 run emitted and where it stopped. The research section must make the papers do argumentative work rather than appear as decoration. The gate section must explain why a stop is a feature of the system. The closing must leave the reader with the exact boundary: governed proof runs can justify local lifecycle movement only when the evidence and gate decision support that movement.

## Evidence burden

The repo proof artifacts carry the local claim: topic discovery, package initialization, research exit, paper intake, essay packet seeding, gate records, run records, and validation records. The claim-boundary ledger governs what those artifacts may be used to say.

The papers carry the external research frame. SWE-AGI and Spec Kit Agents support the shift toward specification-driven and context-grounded agent workflows. SWE-Bench Pro and the Productivity-Reliability Paradox support the reliability caveat. Talk Freely, Execute Strictly supports the separation between flexible language and strict execution. SPECA supports the auditability claim that specifications can produce explicit, inspectable properties.

The synthesis claim is that proof runs are the content-repo version of this broader movement toward explicit specification, validation, and audit surfaces. No single paper says that exact sentence.

## Cut order

Cut implementation detail first. Keep only enough command and path detail to make the architecture legible. Cut secondary paper discussion before cutting the local proof anatomy. Cut any release or distribution speculation unless it is framed as future proof work. If the draft bloats, preserve the proof-run object, the gate boundary, and the caveat that publication reliability remains unproven.

## Failure triggers

Return to blueprint hardening if the candidate starts sounding like a generic agent-governance essay, if it implies that a passed local proof equals public release readiness, if the paper section becomes a survey detached from the local proof object, or if `content-agent` is described as an authority layer rather than the runtime that executes declared workflow contracts.
