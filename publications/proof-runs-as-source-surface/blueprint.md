# Proof Runs As Source Surface Blueprint

## Thesis

For autonomous content work, the trustworthy artifact is the governed proof run: a declared workflow, admitted context, bounded tools, validation outputs, review gates, and resumable evidence that make agent progress inspectable before humans approve lifecycle movement.

## Public Enemy

The false proxy is "the agent finished, therefore it worked." A completion transcript can show activity without proving that the work was bounded, grounded, validated, approved, or safe to resume.

## Core Distinction

- `workflow.yaml` declares the behavior and gate boundary.
- `status.yaml` declares package state.
- `harness_policy.yaml`, `gate_contracts.yaml`, and `pipeline_profiles.yaml` resolve policy, gate class, and route.
- `content-agent` turns those surfaces into resolved runs, run records, review gates, and resume records.
- Reviewable-run evidence records what actually happened.

The article should not collapse these into one "status file" story. The claim is that proof emerges from the separation between source authority, runtime execution, and evidence.

## Evidence Frame

The current evidence set supports a bounded first essay object:

- SWE-AGI shows that specification-driven construction is becoming feasible while production-scale reliability remains unresolved.
- Spec Kit Agents shows the value of context-grounding hooks and validation hooks around agent workflow phases.
- SWE-Bench Pro shows that long-horizon industrial tasks still expose major reliability gaps and that requirements/interface augmentations materially change outcomes.
- The Productivity-Reliability Paradox frames specification discipline as the binding constraint for dependable AI-assisted development.
- Schema-gated workflow and specification-anchored audit papers support the distinction between flexible language interaction and strict execution authority.
- The repo's Phase 2 proof run supplies local evidence: topic discovery was bounded by runtime inputs, wrote declared artifacts, passed a packet gate check, and stopped at a lifecycle gate before package initialization.

## Claim Boundaries

Allowed claims:

- Phase 2 can produce a governed local proof run to a lifecycle gate.
- The proof record is more reviewable than a raw transcript because it exposes admitted context, selected workflow, output targets, gate IDs, approval dimensions, and resume boundaries.
- Specification surfaces need runtime and evidence surfaces before they can carry trust.

Disallowed claims:

- Full autonomous publication is proven.
- External mutation safety is proven.
- A benchmark result by itself proves editorial reliability.
- Package initialization or lifecycle movement should happen without gate approval.

## First Draft Shape

1. Open with the difference between an impressive transcript and a reviewable proof.
2. Show the Phase 2 run anatomy.
3. Use the papers to explain why specification and validation are now central to agent dependability.
4. Explain why gates are not bureaucracy; they are the boundary between probabilistic work and authorized lifecycle movement.
5. Close with the bounded claim: governed proof runs are a credible source surface, but publication reliability still has to be proven stage by stage.
