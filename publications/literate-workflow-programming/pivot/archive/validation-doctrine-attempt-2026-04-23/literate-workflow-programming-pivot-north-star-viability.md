# Pivot North-Star Viability

## Candidate

`Validation Is Lifecycle Infrastructure`

## Field-Reordering Move

The candidate tries to relocate the locus of agent-system debugging and governance.

Its strongest move is:

- workflow specs and policy surfaces are already governing layers
- validation is the infrastructure that keeps those layers attached to actual evidence and allowed behavior
- terminal QA and runtime-only diagnosis are therefore looking too late and too low in the stack

## False Proxy Or Public Enemy

The false proxy is the belief that validation is mainly an end-of-line test suite or review step.

The public mistake underneath the donor package is narrower and stronger:

- operators keep treating workflow surfaces as commentary
- then expect runtime logs alone to explain failure

That is a real enemy. The current problem is scale: the candidate has not yet proved that this enemy is large enough to anchor a north-star flagship essay rather than a sharp doctrine piece.

## Evidence Aperture

The current aperture is good enough for grounding and too thin for north-star clearance.

What the evidence clearly supports:

- validation spans prompt analysis, checks, trace comparison, diagnosis, and refinement
- source-like workflow surfaces need validators and policy to become governable objects
- traces and drift checks are useful because source expectations already exist
- the current package has a local proof example in `spec-diff`

What the evidence does not yet clearly support:

- a larger public reorder outside workflow-governance and agent-engineering discourse
- a sufficiently wide consequence surface beyond "validate earlier"
- a flagship object that can sustain pressure without re-expanding into the full architecture stack

## Doctrine Or Operator Consequence

If the thesis is right, operators should:

- treat validators, contradiction checks, and drift checks as lifecycle infrastructure rather than trailing QA
- stop assuming the real system only lives in hidden implementation
- preserve source / policy / evidence alignment continuously instead of diagnosing divergence after runs go bad

That consequence is real. It is not yet obviously large enough for a top-cluster flagship essay.

## North-Star Verdict

`not_north_star_viable`

## Required Follow-Through

- Keep this as the strongest grounded successor, not as a cleared new flagship object.
- Run one targeted research pass on consequence, public enemy, and cross-context stakes before any sibling package is opened.
- Keep `You're Debugging The Wrong Layer` as the wrapper pressure, not as the candidate itself.
- Keep `Traces Are Not Provenance` and claim-level auditability as supporting seams unless the consequence pass demotes the current candidate.
