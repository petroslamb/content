# Pivot Slate

## Status

This slate records the first post-ceiling rerank from tracked package state only.

The later review in [`literate-workflow-programming-pivot-grounding-review.md`](literate-workflow-programming-pivot-grounding-review.md) keeps one candidate alive as a grounded successor, blocks one attractive wrapper, and holds the rest below the current lead.

## Purpose

This slate exists to decide what should absorb the strongest surviving assets from the capped `Literate Workflow Programming` flagship attempt.

## Scoring Axes

- `Debate gain`: how much larger or more field-reordering the argument becomes
- `Aperture gain`: how much territory opens beyond the capped stack-summary frame
- `Doctrine utility`: how clearly the essay changes operator behavior
- `Opening power`: how naturally the donor assets yield a forceful public opening
- `Synthesis headroom`: how much room the object has to combine current evidence without collapsing into survey

Scores are `1-10`. Higher is better.

## Candidate 1: Validation Is Lifecycle Infrastructure

- Object type: Doctrine-heavy flagship essay
- One-sentence promise: Once workflow specs start governing behavior, validation stops being terminal QA and becomes the lifecycle infrastructure that keeps source, policy, and evidence attached to reality.
- Reuses from donor object:
  - the `spec-diff` opening and local proof
  - the "debugging the wrong layer" accusation
  - the source / validation / trace / provenance stack
  - the validation hinge already stabilized in the claim ledger
- Evidence delta needed:
  - stronger consequence outside repo-shaped workflow examples
  - a sharper public enemy than "test earlier"
  - cleaner proof that lifecycle validation changes operational outcomes rather than only engineering posture
- Why it could break the ceiling: It reorganizes the donor around one doctrine hinge instead of making the reader walk the whole architecture stack.
- Kill criteria:
  - the object still needs a full stack tour to feel consequential
  - the argument collapses into process hygiene or DevOps slogan
  - the consequence never grows beyond "validate sooner"
- Scores:
  - Debate gain: `8.5`
  - Aperture gain: `8.5`
  - Doctrine utility: `9.5`
  - Opening power: `8.5`
  - Synthesis headroom: `8.5`
  - Total: `43.5`

- Reuses from donor object:
  - the strongest opening sentence family from `r3`
  - validator drift as a local proof
  - the late-diagnosis consequence from the ceiling report
- Evidence delta needed:
  - a stable underlying variable beyond the accusation itself
  - stronger cross-domain evidence that workflow-layer failure outruns runtime-only diagnosis

- Why it could break the ceiling: It keeps public pressure alive longer than the capped flagship frame and gives the package a real antagonist.
- Kill criteria:

  - the evidence supports the underlying doctrine but not the headline object
  - the package simply reproduces the `r3` ceiling in sharper prose
- Scores:

## Candidate 4: Workflow Is A Namespace

- Object type: Conceptual bridge essay

- Reuses from donor object:

  - the package map / index vocabulary
- Evidence delta needed:

- Why it could break the ceiling: It would keep the essay out of stack summary by centering one synthesis move.
- Kill criteria:

  - the object feels conceptually tidy but operationally thin
