## Promise

The candidate should argue that AI-native software work is moving the practical source of truth upstream from generated implementation alone into governed specification surfaces: artifacts that are maintained, constrained, validated, typed, linted, trace-linked, or executed by a harness. The essay must make this larger than an agent-workflow niche while staying narrower than the forbidden claim that natural language is code. The public error is `vibe`: treating intent as informal prompt material while only the generated code deserves governance.

## Spine

1. Opening pressure: name the source-of-truth mistake created by vibe coding and agentic code generation.
2. Definition: establish `specification surface` as the governing object, separating it from loose prose, ordinary README text, and one-off prompts.
3. Evidence stack: show how specification-as-program, natural-language harnesses, agent specification languages, executable constraints, test-driven agent definitions, and validation or trace systems give these surfaces operational force.
4. Boundary pressure: use AGENTS.md, Agent README, context-file, controlled-language, and professional-control evidence as bridge material with visible caveats.
5. Source-of-truth doctrine: explain why generated code, traces, tests, and run logs become derived surfaces unless the maintained specification remains inspectable and governable.
6. Operator consequence: close on what teams must maintain, review, lint, validate, and trace if they want AI-assisted work to stay controllable.

## Paragraph burden

The opening must make the antagonist concrete without turning the essay into a general vibe-coding complaint. The definition section must give the reader a portable term and a usable exclusion test: passive prose does not count unless it is connected to control, validation, typing, linting, runtime interpretation, or traceability. The evidence section must let the papers do visible work rather than serving as ornament. The boundary section must prevent overclaiming by keeping context files metric-specific and controlled natural language conditional. The doctrine section must preserve implementation and logs as important downstream artifacts while making the maintained specification surface the place where intent can be governed. The ending must leave the reader with an operator standard, not just a conceptual reframing.
