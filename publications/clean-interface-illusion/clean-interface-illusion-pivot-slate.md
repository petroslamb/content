# Pivot Slate

## Status

This slate records the pre-grounding candidates.

The later review in [`clean-interface-illusion-pivot-grounding-review.md`](clean-interface-illusion-pivot-grounding-review.md) did not clear any of these as a north-star pivot yet.

## Purpose

This slate exists to decide what should absorb the strongest assets from the capped `clean-interface-illusion` flagship attempt.

## Scoring Axes

- `Debate gain`: how much larger or more field-reordering the argument becomes
- `Aperture gain`: how much conceptual territory opens beyond benchmark interpretation
- `Doctrine utility`: how clearly the essay changes operator behavior
- `Opening power`: how naturally the current evidence yields a memorable opening
- `Synthesis headroom`: how much room the object has to combine current and adjacent evidence without collapsing into survey

Scores are `1-10`. Higher is better.

## Candidate 1: Capability Is Not Delegation

- Object type: Flagship thesis essay
- One-sentence promise: The field keeps confusing signs of capability with permission to hand work over, but real delegation depends on reliability, legibility, intervention structure, and bounded failure behavior.
- Reuses from donor object:
  - `tau-bench` opening anomaly
  - `WebSuite` / `WebForge` comparative turn
  - benchmark-to-deployment trust critique
  - routing, fallback, and checkpoint doctrine
- Evidence delta needed:
  - human oversight structure
  - uncertainty-aware delegation
  - contextual information for handoff decisions
  - runtime governance and risk-controlled execution
- Why it could break the ceiling: This expands upward from benchmark interpretation into the real downstream question operators care about: not whether the system can act, but whether the task can be handed over.
- Kill criteria:
  - the phrase collapses into a user-education slogan
  - the argument cannot name a deeper variable than "people overtrust demos"
  - adjacent papers do not cohere around delegability as a real operational distinction
- Scores:
  - Debate gain: `9.5`
  - Aperture gain: `9.5`
  - Doctrine utility: `9`
  - Opening power: `8.5`
  - Synthesis headroom: `9`
  - Total: `45.5`

## Candidate 2: Evaluation Is Governance

- Object type: Doctrine-heavy flagship essay
- One-sentence promise: evaluation systems are not neutral scoreboards; they shape what gets deployed, how much supervision is required, and what risks are treated as acceptable.
- Reuses from donor object:
  - the benchmark-interpretation critique almost directly
  - reliability versus success-rate contrast
  - deployment review doctrine
- Evidence delta needed:
  - explicit governance and supervision literature
  - runtime control frameworks
  - oversight versus control distinction
- Why it could break the ceiling: It turns the current diagnosis into a stronger operator rule and gives the essay clearer institutional consequence.
- Kill criteria:
  - the evidence only shows evaluation influencing governance rather than constituting it
  - the essay drifts into managerial abstraction
  - the object reopens a policy discourse without enough deployment texture
- Scores:
  - Debate gain: `8.5`
  - Aperture gain: `8.5`
  - Doctrine utility: `9.5`
  - Opening power: `7.5`
  - Synthesis headroom: `8.5`
  - Total: `42.5`

## Candidate 3: The Delegability Gap

- Object type: Coined-concept flagship essay
- One-sentence promise: the key variable missing from current agent discourse is delegability: the distance between task performance and trustworthy handoff.
- Reuses from donor object:
  - the capability versus trust distinction
  - repeated-run instability as a delegation problem
  - bounded-failure versus unstable-failure doctrine
- Evidence delta needed:
  - direct delegation literature
  - uncertainty and collaboration signals
  - oversight studies that show what makes risky moments legible
  - one stronger seam on failure cascades or consequential harm
- Why it could break the ceiling: It names the variable the donor essay only implied and gives the next object a portable conceptual engine.
- Kill criteria:
  - the concept feels invented rather than evidenced
  - it becomes too inward or jargon-shaped for a flagship essay
  - the adjacent evidence supports oversight and uncertainty, but not a stable overarching variable
- Scores:
  - Debate gain: `9`
  - Aperture gain: `9`
  - Doctrine utility: `8.5`
  - Opening power: `8`
  - Synthesis headroom: `9`
  - Total: `43.5`

## Candidate 4: Split And Promote

- Object type: Package move rather than a flagship thesis object
- One-sentence promise: publish `r3` as a strong non-flagship piece and start a separate flagship essay later.
- Reuses from donor object:
  - all existing writing work
  - current package cleanliness and review history
- Evidence delta needed:
  - minimal for publication
  - still requires a separate flagship object afterward
- Why it could break the ceiling: It stops forcing one essay to do two jobs and preserves a publishable piece.
- Kill criteria:
  - no new flagship object appears quickly afterward
  - the package move is mistaken for a breakout argument
- Scores:
  - Debate gain: `6.5`
  - Aperture gain: `6`
  - Doctrine utility: `6.5`
  - Opening power: `5`
  - Synthesis headroom: `6`
  - Total: `30`
