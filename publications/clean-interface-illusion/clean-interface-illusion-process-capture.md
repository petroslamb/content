# Process Capture

## Purpose

This file records how the post-ceiling pivot process actually ran inside this leaf package so the workflow can later be extracted, hardened, or revised without reconstructing the sequence from scattered artifacts.

It is not the same thing as the essay argument. It is the local process ledger.

## Package Role

This package began as a flagship essay attempt under `The Clean Interface Illusion`.

That object hit a frame ceiling during essay iteration and became a donor object for post-ceiling pivot discovery.

### 9. Focused scope test on the winner

The package then ran the narrowest decisive test it had left:

- if the winner is explicitly scoped to verification-dependent advisor workflows rather than all human-AI collaboration, does it finally clear?

Method:

1. search refresh on verification, independent aggregation, and advisory workflows
2. paper-level inspection of the exact boundary papers
3. one fresh short assistant judgment on the scoped object

Result:

- still `no`

Why still blocked:

- the verification-boundary papers show the limiting factor can be task verifiability itself, not only degraded human competence
- narrowing the scope helps, but does not by itself convert the seam into a validated north-star object
- the object still looks more like a workflow-design heuristic than a fully cleared flagship research agenda

This is an important workflow lesson:

- explicit scope narrowing should be tested directly, not assumed to solve a blocker

### 10. Threshold search and winner demotion

After the scoped winner still failed to clear, the package ran one more search-first pass on the newly sharpened blocker:

- are there domain-calibrated thresholds for preserved understanding or oversight?

Result:

- essentially no direct anchors beyond the conceptual threshold paper itself

The assistant's judgment on that absence was:

- demote `Corrective Competence / Capability-Comprehension Gap`
- promote `Verification-Preserving Workflow Design` as the stronger next object

Why:

- workflow-preserving structures are more observable and grounded than internal threshold claims
- the new object preserves the normative aim of human oversight without requiring already-calibrated comprehension thresholds
- the package now has a cleaner measurement target: contestability events, overrides, and preserved verification affordances

This is another workflow lesson:

- a clear conceptual winner can still lose if the final measurement anchor never materializes
- negative search results can legitimately trigger demotion instead of indefinite waiting

### 11. Workflow-layer contestability pass and comparative rerank

The package then ran a focused pass on workflow-preserving alternatives:

- contestability
- provenance
- independent aggregation
- preserved expert checkpoints

This produced a stronger workflow object:

- `Contestability-Preserving Workflow Design`

But a final comparative rerank across the live candidates restored:

- `Corrective Competence / Capability-Comprehension Gap`

as the top-ranked provisional candidate.

Why:

- the threshold search was a real blocker, but not enough on its own to dislodge the conceptual leader once the full evidence set was compared against the alternatives
- contestability improved the package's understanding of the workflow layer, but did not yet outperform corrective competence as the best flagship pivot candidate

This is a stronger workflow lesson than either half alone:

- negative blocker searches matter
- but package ranking should be governed by comparative candidate quality, not by a single failed rescue move in isolation

### 12. Behavioral-proxy pass and candidate stabilization

The package then ran a pass focused on practical proxies in expert domains:

- directional change against AI
- normalized weight-of-advice
- automation-bias rate
- confirmation-bias coefficients
- Brier score and over/under-reliance
- hypothesis-selection behavior

Result:

- `Corrective Competence / Capability-Comprehension Gap` became the clear lead candidate
- but it still did not clear as a real flagship pivot

Why:

- the new papers did not solve every missing layer
- but they converted the threshold problem from purely abstract calibration into a measurable family of behavioral signatures
- that was enough to stabilize the ranking in favor of corrective competence over its remaining rivals

### 13. Full-package clearance pass

The package then ran one final synthesis pass against:

- the corrective-competence seam
- the workflow and contestability seam
- the strongest appropriate-reliance intervention papers
- the behavioral-proxy papers

Result:

- `Corrective Competence / Capability-Comprehension Gap` cleared as a north-star pivot

Why:

- the seam now has formal constructs, degradation evidence, domain-expert behavioral proxies, and rival intervention papers that mostly improve calibration or verification without eliminating the deeper human-AI gap
- the remaining problems were downgraded from blocking gaps to residual blueprint risks

## Discovery Modes Compared

### Mode A: brainstorm-first

Used earlier for:

- `Capability Is Not Delegation`

Properties:

- fast
- good for generating bold candidates
- weaker grounding
- higher risk of attractive but under-supported pivots

### Mode B: search-first, assistant-second

Used for:

- `From Accuracy to Readiness`
- `Corrective Competence / Capability-Comprehension Gap`

Sequence:

1. targeted alphaXiv search
2. paper-level abstract or summary inspection
3. short fresh assistant comparisons on the retrieved seam

Properties:

- slower at first
- materially better at surfacing supportable candidates
- better for north-star gating

This package now treats Mode B as the default for pivot discovery.

## Reusable Workflow Pieces Recovered Here

These are the concrete pieces that now exist in the package and are candidates for workflow extraction later:

1. `Post-ceiling reframe`
   Purpose: explicitly freeze the donor object and state what survives.

2. `Pivot slate`
   Purpose: score multiple materially different candidates before search deepens.

3. `Grounding review`
   Purpose: record whether any candidate has actually cleared a research gate.

4. `Pivot blocker`
   Purpose: preserve why a tempting candidate was rejected so it is not rediscovered later as if new.

5. `Next pivot candidate`
   Purpose: maintain one active winner candidate without pretending it is already cleared.

6. `Candidate-specific research delta`
   Purpose: define the exact gaps that the next pass must close.

7. `Discovery mode note`
   Purpose: distinguish brainstorm-first candidates from search-first candidates.

## Workflow Lesson So Far

The package now supports one strong provisional workflow conclusion:

- after a flagship frame ceiling, do not jump directly into a new flagship draft
- first run post-ceiling reframe, pivot slate, and grounding review
- treat candidate discovery and candidate clearance as separate stages

That lesson should survive even if the current winner candidate later gets blocked.
