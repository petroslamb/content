# Rewrite Ledger: V6 Essays to V7 Doctrine Bundle

Internal drafting support for the `Operating Agents` `v7` rebuild.

The `v6` pass solved the central problem of the package. It proved that the essay layer could be governed by a real law stack rather than by generic essay polish. The `v7` pass exists because proof is not the same thing as inevitability. The bundle still shows too much of its construction. Several essays still announce their method too visibly, the launch note still exposes package plumbing, and the series occasionally reads like one disciplined template repeated seven times.

The `v7` question is therefore stricter than the `v6` question. It is no longer "can these pieces become doctrine-first essays?" It is "can this bundle read like the public language serious builders should carry into design review next week?"

## What V6 Got Right

- the seven-law stack is real
- the enemy mistakes are mostly named cleanly
- the core essays already prefer doctrine over taxonomy
- the companions already behave like second-pass breadth essays rather than appendices
- the essay layer has a visible builder audience instead of a generic AI readership

Those gains should not be thrown away. They should be hardened.

## Why V7 Exists

`v6` still stalls below the full target for five reasons.

First, the launch note still behaves partly like package explanation instead of pure public preface.

Second, too many essays use the same opening machinery. A sharp operational anecdote works. Seven variations of the same rhetorical move create bundle drag.

Third, several closes are still too similar. The series accumulates doctrine well, but it does not always accumulate momentum.

Fourth, the case universe is still narrower than the package ambition. Too many failures live in adjacent administrative surfaces.

Fifth, the public essays and companions still share a little too much sentence DNA. The split is conceptually sound, but the tonal separation can get cleaner.

## V7 Working Goal

The `v7` bundle should feel authored from inside one field position.

That means:

- each public essay can stand alone as a Substack post
- the full run reads like one doctrine stack rather than one template
- each chapter owns one law, one enemy mistake, one failure archetype, one decision rule, and one escalation rule
- each chapter contains at least one sentence a builder could quote in an architecture argument without extra explanation
- the companions broaden the terrain without sounding like expanded public drafts

## Non-Negotiable V7 Rules

- `v7` files are new sibling files. Do not overwrite `v6`.
- every public essay keeps a `## Selected Sources` tail
- every companion keeps a `## Sources Behind This Chapter` tail
- public essays must keep at most one compact structured artifact
- companions may use one compact comparison device only if prose cannot carry the distinction
- no essay should preserve blueprint completeness at the expense of public force
- no companion should repeat the essay opening shape or simply restate the law in slower form

## Rewrite Sequence

### Phase 1: Lock The Packs

Write the doctrine packs first and refuse to draft outside them.

### Phase 2: Rebuild The Core Essays

Rewrite in this order:

1. launch
2. reasoning
3. safety
4. optimization
5. action
6. memory
7. multi-agent

That order attacks the chapters most exposed to blueprint relapse, then re-tunes the stronger pieces against the rebuilt series frame.

### Phase 3: Rebuild The Companions

Each companion should be rewritten only after its public essay is stable. The job is not overflow. The job is second-pass terrain.

### Phase 4: Rebuild The Bundle Surfaces

Create `operating-agents-coverage-map-v7.md` and update the essay-layer READMEs so the package presents `v7` as current and `v6` as archived baseline.

### Phase 5: Run The Differentiation Pass

Read the full sequence and cut:

- repeated opening cadence
- repeated closing cadence
- repeated "paper X mattered because" scaffolding
- repeated enterprise-admin scenery
- repeated explanatory sentences that make two chapters sound interchangeable

## Acceptance Gates

### Public Essay Gate

Every `v7` essay must pass all of these checks:

- the doctrine law appears in the first fifth
- the enemy mistake is explicit
- the failure archetype is memorable
- the decision rule is actionable
- the escalation rule is severe and legible
- the body keeps returning to one architecture argument
- the `## Selected Sources` tail supports the doctrine instead of listing background reading

### Companion Gate

Every `companion-v7.md` must pass all of these checks:

- it opens differently from the essay
- it owns omitted terrain rather than retelling the public piece
- it extends the source surface without collapsing into taxonomy sprawl
- its `## Sources Behind This Chapter` tail has three jobs:
  core sources
  adjacent or omitted sources
  relation to essay, blueprint, and paper notes

### Bundle Gate

The full set should pass these checks:

- a builder can summarize the bundle as seven laws and seven enemy mistakes
- no two chapters feel like the same essay with different nouns
- the launch note reads as a public preface rather than a package README
- the companions feel like second-pass essays rather than annexes
- the coverage map and READMEs all point to the same `v7` reading path

## Review Questions

- What architecture argument does this chapter help a builder win?
- What bad default does this chapter make harder to defend?
- What sentence from this chapter is worth quoting?
- What material is still here only because the blueprint once carried it?
- What did the companion gain because the public essay got stricter?
