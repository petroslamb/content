# Publishing Outline

Use this outline when turning the framework into a public essay, note, or short series.

## Piece 1: Why Traces Are Not Enough

Core argument:

- agent demos overvalue visible traces
- real operators need more than a trace
- trust, approval, debugging, and postmortem review all depend on missing context

Deliverable:

- a short argument-led essay that introduces the problem

## Piece 2: The Reviewable Runs Model

Core argument:

- the framework is a run reviewability model, not interpretability work
- the six review questions are the core interface
- runtime records and governance records should scale by risk

Deliverable:

- a model doc or public essay explaining the six questions, the three layers, and the risk-tier standard

## Piece 3: Proof From A Real Run

Core argument:

- raw logs alone leave review gaps
- a reconstructed review packet improves inspection quality
- the value is operational, not decorative

Deliverable:

- a side-by-side public writeup based on `proofs/coding-real-run/comparison.md`

## Publication Rule

Do not publish the framework as a strong claim until the public package can point to:

- the core model
- the minimal operational standard
- one real proof artifact

Without those three pieces, the framework still reads as mostly conceptual.
