# Coverage Gaps

This file turns “we need more runs” into a finite acquisition plan.

## Already Covered Well Enough

- internal coding/package runs
- repo/refactor runs
- external-action third-party platform runs
- publish/deploy runs

These categories already have enough real evidence to support meaningful framework calibration.

## Partially Covered

- artifact-generation runs
- workflow-ops runs
- limit-finding runs
- editorial runs

These categories are represented, but still too lightly to count as broadly calibrated.

## Missing And High-Priority

- retrieval-heavy governed-output run
- stronger browser held-submit or pre-submit run
- one real degraded or partial-reconstruction case
- one real near-miss or failure-review case with meaningful operational consequence

These categories would most improve the framework’s empirical range and tuning quality.

## Missing And Optional

- multi-agent run with credible attribution demands
- long-horizon repeated-run pattern
- self-hosted or scheduled automation run with recurring governance boundary

These would deepen the framework further, but they are not the next bottlenecks.

## Acquisition Rule

Prefer the next run that adds a new run class, boundary type, or verification mode over a better-polished duplicate of a category that is already covered well enough.
